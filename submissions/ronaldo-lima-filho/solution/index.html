Inicie o servidor local para usar o aplicativo

  1. Abra um terminal na pasta submissions/ronaldo-lima-filho/ extraída do ZIP e execute: 
    cd solution
python3 -B app.py
    É necessário Python 3.10 ou superior. Se já estiver na pasta solution, execute somente o comando Python.
  2. Mantenha esse terminal aberto enquanto usa o aplicativo.
  3. Com o servidor Python rodando, acesse:
    http://127.0.0.1:8765/

O servidor lê os CSVs da pasta solution/data/. Abrir o arquivo index.html diretamente não inicia esse serviço.

Metodologia, fonte e limites

Filas operacionais: conversão; saneamento (>120 dias OU >2,5× mediana de ciclo Won do produto); qualificação (Prospecting ou início sem data válida). Conversão destaca 1–2× o ciclo, com fallback de 30–90 dias quando não há mediana positiva. São critérios propostos de atenção, sem diagnóstico de esfriamento. Baseline por idade continua disponível. A base não contém a data do último contato. Segundo a fonte, a idade considera o início de Engaging; não há histórico para validar reentradas ou tempo contínuo na etapa. Índice opcional de até 80 pontos: fase + idade + catálogo. Não é probabilidade de conversão nem confiança.

Completude não valida correção: os quatro campos de contexto são conta, produto, vendedor e data. “Limitada”/“parcial” são rótulos operacionais, não confiança estatística. Sem data não é baixa urgência comprovada. Os comparáveis, ciclos históricos e atributos de conta não acrescentam pontos. Ciclos históricos orientam somente a fila operacional, separada do índice-base.

Won e Lost ficam fora da fila. close_value e close_date não entram no score. Fechamentos anteriores à referência compõem o histórico da conta (Won/Lost) e o ciclo mediano do produto (Won). Dados de fechamento da oportunidade aberta nunca entram no cálculo. Sem versões históricas dos atributos de conta, isto é uma demonstração retrospectiva, sem backtest temporal.
